# API Reference

All routes live under `app/api/**/route.ts`. Every route is real — it authenticates via Clerk, then delegates to a `core/{domain}/services` function backed by Prisma. None of these return mocked data.

Route protection: `proxy.ts` (Clerk middleware) requires a signed-in session for everything except the public allowlist (`/`, `/login`, `/signup`, `/sso-callback`, `/onboarding`, `/api/webhooks`, `/api/cron`, `/invite-error`). Owner-only routes additionally call `requireOwnerClub()`, which derives `clubId` from the caller's own `UserProfile` — a client can never pass a `clubId` to act on a different club. `/api/cron/*` isn't Clerk-protected at all (Vercel Cron has no session) — it checks its own `CRON_SECRET` bearer token instead.

## Tournaments (owner-facing, club-scoped)

Doubles padel tournaments: group stage → knockout bracket. Every route below is gated by `requireOwnerClub()`; every mutating route (`POST`/`PATCH`) additionally gates on `requireClubOperational()` — 403 `club_inactive` or `club_mp_not_connected` if the club isn't operational. `GET` routes deliberately skip that second gate so an owner can still read their own data regardless of operational status.

| Method | Route                                                                                      | Description                                                                                                                                                                                                                                                                                                                             |
| ------ | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/api/clubs/tournaments`                                                                   | Create a tournament plus its initial categories in one transaction. Body: `{name, description?, registrationOpensAt, registrationClosesAt, startDate?, endDate?, categories: [{name, groupCount, advancesPerGroup, minCategoryLevel?, maxCategoryLevel?, maxTeams?}]}` — at least one category is required. Created as `status: DRAFT`. |
| GET    | `/api/clubs/tournaments`                                                                   | List the caller's own club's tournaments.                                                                                                                                                                                                                                                                                               |
| GET    | `/api/clubs/tournaments/[tournamentId]`                                                    | Tournament detail (with categories), scoped to the caller's own club.                                                                                                                                                                                                                                                                   |
| PATCH  | `/api/clubs/tournaments/[tournamentId]`                                                    | Update name/description/registration window/start-end dates. Categories aren't editable through this route.                                                                                                                                                                                                                             |
| POST   | `/api/clubs/tournaments/[tournamentId]/publish`                                            | `DRAFT` → `REGISTRATION_OPEN`, sets `publishedAt`. 409 if the tournament isn't currently `DRAFT`.                                                                                                                                                                                                                                       |
| POST   | `/api/clubs/tournaments/[tournamentId]/cancel`                                             | Transitions the tournament to `CANCELLED`.                                                                                                                                                                                                                                                                                              |
| GET    | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/groups`                     | List a category's groups, each with its assigned teams.                                                                                                                                                                                                                                                                                 |
| POST   | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/groups`                     | Assign teams into groups. Body is a discriminated union on `mode`: `{mode:"manual", groups:[{groupName, teamIds}]}` or `{mode:"auto"}` (balanced automatic assignment).                                                                                                                                                                 |
| POST   | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/groups/lock`                | Locks the category's groups and generates the round-robin `GROUP`-stage matches.                                                                                                                                                                                                                                                        |
| GET    | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/groups/[groupId]/standings` | Computed standings for one group, derived live from its `COMPLETED`/`WALKOVER` matches — not a persisted table.                                                                                                                                                                                                                         |
| GET    | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/groups/[groupId]/matches`   | Plain list of a group's matches.                                                                                                                                                                                                                                                                                                        |
| GET    | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/teams`                      | Registered teams for a category, joined with both players' display names (for the owner UI's group builder).                                                                                                                                                                                                                            |
| POST   | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/matches/[matchId]/score`    | Enter a completed match's score. Body: `{sets: [{setNumber, teamAGames, teamBGames}]}` (1–3 sets, best-of-3). The winner is always derived server-side from the sets, never trusted from the client.                                                                                                                                    |
| POST   | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/matches/[matchId]/walkover` | Record a walkover. Body: `{winningTeamId}`.                                                                                                                                                                                                                                                                                             |
| POST   | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/knockout/generate`          | Seeds group standings into a knockout bracket (fixed ladder, capped at Round of 32).                                                                                                                                                                                                                                                    |
| GET    | `/api/clubs/tournaments/[tournamentId]/categories/[categoryId]/knockout`                   | List a category's knockout-stage matches.                                                                                                                                                                                                                                                                                               |

Note: match scoring/walkover routes live under `.../categories/[categoryId]/matches/[matchId]/...`, not directly under `.../[tournamentId]/matches/...` — a match is always looked up in the context of its owning category.

## Tournaments (player-facing, global — no club scoping)

Unlike the rest of the player-facing surface (`/api/player/*`), these live under `/api/tournaments/*` and are gated by `requireAuthUser()` only, with no club scoping — a player can discover and register across any club's tournaments, not just their home club.

| Method | Route                                                               | Description                                                                                                                                                                                                                        |
| ------ | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/tournaments/open`                                             | Currently-open tournaments across all clubs — either open for registration, or already `REGISTRATION_OPEN`+ and one the caller has a non-withdrawn team in. Powers the nav "open tournaments" badge and the tournaments list view. |
| GET    | `/api/tournaments/[tournamentId]`                                   | Tournament detail for a player: categories, the club's name, and the caller's own teams (`myTeams`).                                                                                                                               |
| POST   | `/api/tournaments/[tournamentId]/categories/[categoryId]/register`  | Register a team for a category. Body: `{partnerId}`.                                                                                                                                                                               |
| POST   | `/api/tournaments/[tournamentId]/teams/[teamId]/withdraw`           | Withdraw the caller's own team.                                                                                                                                                                                                    |
| GET    | `/api/tournaments/[tournamentId]/categories/[categoryId]/teams`     | Registered teams for a category, with both players' display names.                                                                                                                                                                 |
| GET    | `/api/tournaments/[tournamentId]/categories/[categoryId]/standings` | Full standings detail for a category: every group's standings and matches, plus knockout matches grouped by round. Plain data — no bracket graphic.                                                                                |
| GET    | `/api/tournaments/performance-summary`                              | The caller's own tournament performance summary (tournaments played, etc.) — feeds the PlayerOverview dashboard card. Always the caller's own data; never accepts a target player id.                                              |

## Payments

| Method | Route                       | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------ | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| POST   | `/api/webhooks/mercadopago` | Mercado Pago's payment webhook. Unauthenticated (no Clerk session) — instead verifies the `x-signature`/`x-request-id` headers against `MERCADOPAGO_WEBHOOK_SECRET` (see `lib/mercadopago/webhookSignature.ts`) and rejects with 401 on a bad signature. The webhook body itself is never trusted for payment status — it re-fetches the payment by id via an authenticated GET. On an `approved` payment: records the payment against the reservation's invoice and confirms the reservation (`SCHEDULED` → `CONFIRMED`); a duplicate delivery for an already-recorded payment is detected (invoice already `PAID`) and acked as a no-op, while a genuine failure is logged and answered with a 500 so Mercado Pago retries. Every other status (`pending`, `in_process`, `authorized`, `rejected`, `cancelled`, etc.) is a no-op — the invoice is deliberately never voided from here, since Checkout Pro lets a buyer retry with a different card on the same preference, and a later `approved` delivery needs to still find the invoice `ISSUED` to succeed. Publicly reachable via the existing `/api/webhooks(.*)` allowlist entry in `proxy.ts` — no middleware change was needed. |

Cancellation also touches payments: both `POST /api/player/reservations/[id]/cancel` and owner-cancel (`PATCH /api/clubs/reservations/[reservationId]` with `action: "cancel"`) now refund any `COMPLETED` payment via Mercado Pago before cancelling the reservation. A refund failure blocks the cancellation (502) instead of silently proceeding.
